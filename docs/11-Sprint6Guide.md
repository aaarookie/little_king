## 二、我（C++）实现内容

### 1. 对局统计系统

```
ALKBattleGameMode 每局记录（轻量计数器，无额外开销）：
  每阵营：击杀数 / 造成总伤害 / 英雄剩余数
  全局：对局时长 / 是否超时虚弱结束 / 胜者
结算时打一行统计日志（便于收集）：
  [MatchStats] Winner=Player Duration=215.3 Kill=12/9 Dmg=3421/2910 Overtime=0
并提供蓝图查询结构（BP 可读的 FKMatchStats）供结算面板显示
```

### 2. 平衡工作台（无代码，方法论为主）

- 循环：**改数据表 → PIE 一局 → 看 [MatchStats] 日志 → 记录 → 再改**
- 平衡记录模板沿用 Sprint 4 教程 C 的表格，本轮补"胜率/时长趋势"
- 引擎自带神器：PIE 控制台 `slomo 0.5`（0.5 倍速观察细节）/ `slomo 2`（快速压测），**不用写代码**
- 数值快照：改表前把 DA_GameData 相关值记入平衡记录，方便回滚（git 也兜底）

### 3. 稳定性检查清单（我给代码侧清单，你执行 PIE 验证）

- [ ] 单位在移动中被全灭 → 无空引用日志（索敌/分离/波次）
- [ ] 打牌瞬间单位死亡/对局结束 → 无崩溃（放置流程引用安全）
- [ ] 超时虚弱期反复击杀最后一名英雄 → 结算只触发一次
- [ ] 数据表某行缺失 → 只报警告不崩溃（Sprint 2 自诊断日志兜底）
- [ ] 开局 1 秒内快速部署全部英雄 + 开战 → 无异常
- [ ] 连打 3 局内存/帧率稳定（无弹道/单位泄漏）

## 三、你要做的（教程）

### 教程 A：Windows 打包（新手级，中文 UI）

```
① 项目设置（编辑 → 项目设置）→ 打包（Packaging）：
   - 项目名/版本随意
   - 检查"使用 Pak 文件"默认勾选即可
② 平台（Platforms）→ Windows → 目标平台默认
③ 主菜单：文件（File）→ 打包项目（Package Project）→ Windows
   → 选输出目录（如 E:\little_hero\Builds）→ 等待（首次 10~30 分钟，之后增量快）
④ 到输出目录运行：little_king.exe（WindowsNoEditor 文件夹里）
```
> 首次打包常因着色器编译慢——耐心等，别关窗口。失败先看日志（输出目录/Logs）。

**打包版冒烟清单**：
- 部署 → 开战 → 打牌 → 胜负 → 重开（全 UI 流程）
- 音效/飘字/震屏在打包版生效（无编辑器专属依赖）
- 窗口尺寸/DPI 下 HUD 布局正常（用窗口模式跑一遍）

### 教程 B：结算面板接统计

```
WBP_BattleHUD → 结算面板（ResultOverlay）加两个文本行：
  "击杀 X / Y    输出伤害 A / B    时长 T 秒"
蓝图：OnMatchEnded（已有事件）→ 调 GetMatchStats（Sprint 6 C++ 提供）
  → 取字段 → 格式化文本 → 显示
```

### 教程 C：3 连测平衡

```
每天 1 次、每次 3 局，填表：
┌──────┬──────┬───────┬──────┬──────┬──────────────┐
│ 局次 │ 胜方 │ 时长s │ 击杀 │ 观感 │ 本局前改动    │
├──────┼──────┼───────┼──────┼──────┼──────────────┤
│ 1    │      │       │      │      │              │
└──────┴──────┴───────┴──────┴──────┴──────────────┘
判定标准（原型目标）：
  时长 3~5 分钟、胜负差距不悬殊（击杀比 ≤ 2:1）、
  有"差一点就赢"的局 → 平衡可接受；否则回到 Sprint 4 教程 C 的杠杆表微调
```
