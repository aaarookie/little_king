## 阶段一：开始界面、多存档与金币命令

日期：2026-09-13。基线为地牢 D0～D5、家园 H0～H5 以及 BUG-019 点击穿透修复后的工作区。此次改动保留原有未提交内容，不代替其他协作者的交付记录。最近已发布版本仍为 v0.6，本次没有创建发布标签。

### 需求与最终行为

| 功能 | 当前约定 |
|---|---|
| 启动 | 新开一次编辑器 Play 会话先进入 `L_StartMenu`。即使当前编辑的是 `L_Home` 或 `L_BattleTest`，也先跳转开始界面；同一会话的正常地图往返不重复拦截。 |
| 继续游戏 | 选择最近使用或自动保存的有效存档。没有有效档时按钮不可点击。家园/已结束远征进入家园，未结束远征进入既有 D5 恢复流程。 |
| 新的游戏 | 使用编号最小的空位，创建全新 ProfileId；金币 0、建筑 Lv1、默认解锁及战备、没有旧远征。已有档不被覆盖。 |
| 读取存档 | 展示固定 8 格，包含编号、金币、家园/远征状态、保存时间及读取/删除按钮。空位和不可读档不能载入。 |
| 存档上限 | 8 个逻辑存档，每个包含自己的永久进度双副本和远征文件。占满时新建按钮禁用，可通过读取界面删除旧档腾出空位。 |
| 删除 | 先展示编号和删除范围，取消保留全部数据，确认后删除该档的永久进度两个副本及远征文件。 |
| 设置 | 保留按钮和 `OnSettingsRequested` 蓝图事件接口，当前点击仅提示暂未开放。 |
| 金币调试 | `show me the money` 默认给当前档 100 金币；末尾传入非负整数则按指定数量发放。保存成功才改变内存金币，记录实际增加量。 |

开始界面采用原生 UMG，用色块和文字表示骑士、法师、游侠；没有引入新的美术依赖。存档页的时间明确标为 UTC，避免跨时区显示误解。

### 存档兼容与失败保护

1. 存档 01 继续使用 `LittleKing_Profile_A.sav`、`LittleKing_Profile_B.sav` 和 `LittleKing_Run.sav`。已有玩家档自动出现在第一个位置，不复制、不强制迁移、不在打开菜单时写入。
2. 存档 02～08 分别使用 `LittleKing_Save02_Profile_A/B`、`LittleKing_Save02_Run` 等名称。存储路径由当前 GameInstance 的选档结果配置到子系统实例，正式选档不借用全局测试钩子。
3. 每个 Profile 仍执行原有 A/B 轮换、Revision 递增、写后读回校验。新增兼容字段 `SavedAtUtc`；旧文件没有该字段时，排序暂用文件时间。Profile Schema 1、Run Schema 5 和外层 SaveVersion 1 不变。
4. 选中旧档会通过正常 Profile 提交更新时间，使下一次“继续游戏”回到刚选择的游戏。远征的存档时机和战斗恢复粒度沿用 D5，不保存战场 Actor 或逐帧战斗过程。
5. 不可读、未知版本、Profile/Run 身份不一致的文件保留，占用原位置并显示原因；不自动新建覆盖。Profile 的另一份有效副本仍可用于读取。只有旧 Schema 远征尚无 ProfileId 的既有迁移场景允许补建默认家园。
6. 删除先写 `_Profile_Deleting.sav` 标记，再删除该档的 Run、Profile B、Profile A。中途中断时残留数据不可继续，需要重试删除；清空的位置才可复用。其他档不参与删除。
7. 金币命令只在已经选档后生效；开始界面执行不会暗中创建存档。负数、小数、非数字、额外参数、超过 2147483647 的输入拒绝。已有金币与发放量之和达到 int32 上限时封顶，避免溢出。

### 最终行为与暂定设计

| 内容 | 本次实现 |
|---|---|
| 固定版图 | 固定地理种子 `9152026`，选定五个扰动后的区域中心并裁剪为五块凸多边形。版图、入口/出口的位置固定，完整几何也写进远征档。 |

| 固定起终点 | 全局一个起点、一个最终首领出口；中间区域各两个入口/出口。玩家选择上下区域分支之一，通常经过四区，不强制清空所有节点。 |

| 金库 | 出发本金上限暂定 Lv1～5 为 100/150/200/250/300，不能超过家园余额；既有银币产速与上限升级不变。 |
| 金币 | 本金从家园转入远征；途中赚取不受出发上限限制。成功、失败、主动结束全额带回剩余钱包；已消费不返还，通关额外 20 保留。 |
