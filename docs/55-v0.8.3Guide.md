# v0.8.3 试玩与素材教程

更新：2026-10-02。适用于本项目使用的 Unreal Engine 5.8。代码与资源完成导入后可直接启动；以下人工步骤用于观察实际游戏表现和试听，不代表这些项目已经通过人工验收。正式实现与自动测试记录见本轮变更文档，素材来源见 [54](54-v0.8.3Assets.md)。

## 打开当前工程

先停止 Play 并关闭编辑器。新的反射枚举和属性需要完整构建，不依赖 Live Coding。打开 PowerShell，执行：

```powershell
& 'E:\epic\UE_5.8\Engine\Build\BatchFiles\Build.bat' little_kingEditor Win64 Development '-Project=E:\little_hero\little_king\little_king.uproject' -WaitMutex -NoHotReloadFromIDE -gather
```

终端出现 `Result: Succeeded` 后，打开 `E:\little_hero\little_king\little_king.uproject`。点击编辑器上方 Play 会进入游戏开始页。推荐新建一个名称便于识别的验证存档，保留自己的正常进度存档。

## 正常获得法术

九张新法术需要永久研究解锁。法术书在远征市场以已有的低概率书籍规则出现，高阶书籍受区域进度限制；购买后结束或放弃远征将书带回，回家园点击图书馆研究，研究消耗对应书籍。解锁后，在战备处将法术加入远征卡组，再通过大门出征。新建游戏不会直接赠送这些法术，召唤天使也不会成为可选择的独立佣兵卡。

正常流程适合验证解锁和存档，逐张测试法术适合使用本轮提供的隔离测试或预览入口。不要直接修改真实 `.sav` 文件来强行解锁，自动测试也不需要加载玩家存档。

## 安全查看全部新素材

完整构建并导入本批素材后，可在单独进程运行隔离预览。它关闭永久档读写，把远征路由到随机临时名称并关闭自动存储，不进入自己的存档。

```powershell
& 'E:\epic\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe' 'E:\little_hero\little_king\little_king.uproject' '/Game/Maps/L_BattleTest' -game -V083Preview -RenderOffscreen -windowed -forceres -ResX=1920 -ResY=1080 -unattended -nop4 -nosplash
```

预览依次显示五角色的全部 16 个姿态、九张法术卡图、向左和向右的实际位移步态，以及黑云、冰冻和飓风范围。约 730 个已就绪渲染帧后自动退出；首次着色器编译时会等待，不把灰色占位材质算作正式截图。输出在 `Saved/Screenshots/V083`，日志应出现 `V083_PREVIEW_OK`。将 `ResX/ResY` 改为 `1280/720` 可以检查较小窗口。

预览通过手工取动画帧展示美术，并通过组件位移演示步行。它冻结战斗演员，保留原生范围绘制，用于查图、步态和字体；画面中的满血角色不是战斗逻辑验收。九法术的真实召唤、索敌、伤害、治疗和冷却仍由专项测试与正常战斗试玩验证。

需要亲自操作九法术时，可启动交互式隔离试玩；保留声音与可见窗口，不加 `RenderOffscreen`、`nosound` 或 `unattended`：

```powershell
& 'E:\epic\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe' 'E:\little_hero\little_king\little_king.uproject' '/Game/Maps/L_BattleTest' -game -V083Sandbox -windowed -ResX=1280 -ResY=720 -nop4 -nosplash
```

正常部署三名英雄后，九张新法术会随机进入手牌，无需研究；银币上限为 20，每秒获得 2。九牌卡组仅为调试突破 8 格容量，正常出征规则不变。该独立进程关闭永久档读写，使用随机 UUID 的临时远征且关闭自动保存，不产生永久解锁。试玩完直接关闭窗口；正常编辑器 Play 不启用此入口。

需要核对实际 UMG 手牌与祝福冷却，可使用自动 UI 预览：

```powershell
& 'E:\epic\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe' 'E:\little_hero\little_king\little_king.uproject' '/Game/Maps/L_BattleTest' -game -V083HUDPreview -RenderOffscreen -windowed -forceres -ResX=1920 -ResY=1080 -unattended -nop4 -nosplash
```

该入口同样隔离存档，自动实际施放神圣祝福，约 110 个已就绪渲染帧后退出。检查 `Saved/Screenshots/V083/HUDCooldown_1080.png` 中四张互不重复的增援牌与祝福计时，日志完成标志为 `V083_HUD_PREVIEW_OK`；改为 `1280/720` 时文件名为 `HUDCooldown_720.png`。它使用五张调试牌验证祝福冷却后四槽补满，正常出征仍至少七张。

本轮素材预览和自动 UI 已在 720p／1080p 实际运行，原生倒计时降至约 148.3 秒时界面显示“149 秒后可抽取”，银币也从施放后的 12 增长到约 15.3。交互入口使用相同的存档隔离与正常战斗计时，供自行试玩和试听；这些渲染记录不代替声音的主观听感验收。完整证据见 [56](56-v0.8.3ReleaseNotes.md)。

## 观察九种法术

| 法术 | 建议观察的实际效果 |
| --- | --- |
| 冰冻法术 | 对多名敌人施放后观察三秒不能移动、普攻和主动施法；结束后恢复正常 |
| 三阶增援 | 选一个宽敞地点，确认一次出现剑盾、短弓和法杖三类天使；优秀、稀有、史诗品质文字与数值分别匹配 |
| 神圣增援 | 确认召唤审判者与牧师长两名传说单位；牧师长治疗受伤友军，不用普攻伤害敌人 |
| 黑云 | 在双方交战处施放，观察范围内单位的隐藏状态与攻击者重新选目标；范围伤害仍可以命中隐藏单位 |
| 雷电 | 范围内先出现一次打击，约 0.2 秒后出现第二次；英雄不会成为这两次打击的目标 |
| 飓风 | 矩形与向右提示清晰，双方可移动角色持续向战场右侧移动；方向以画面右侧为准 |
| 神圣祝福 | 受伤佣兵恢复到满血，存活英雄恢复最大生命的一部分；已经失能的英雄保持失能；施放后 150 秒内不会重新抽到 |

增援法术即使法师失能仍有全场落点权限。天使牧师与牧师长的基本工作是治疗，不拥有额外的被动或主动技能。新施法效果不产生镜头震动；仅火球继续触发当前的小震动。

顺便观察天使向左、向右和斜向移动是否与精灵朝向一致，移动的四帧是否形成两次明确迈步。让角色和营地重叠时，画面应沿用既有的地面排序规则。天使质量共享美术，不要求稀有和史诗重新绘制一套角色。

## 试听与显示检查

先在 1280×720 的独立游戏窗口测试，再改为 1920×1080。观察卡图是否等比显示，费用、阶位和说明是否可读，天使轮廓是否被武器或翅膀裁切。冰冻、隐藏和受击标记应能区别，飓风矩形不能被当成圆形范围。

在正常战斗音量下分别试听冰冻、增援、黑云、雷电、飓风和祝福。它们应是短提示，而不是持续循环或反复堆叠的噪声。雷电设计为轻雷，不应压过主要战斗信息。若声音不合适，记录法术、场景、主观音量与问题描述，后续可调整 WAV 峰值或 SoundMap 对应资源。真实听感由实际播放设备决定，自动格式检查不能代替试听。

## 可选的素材重新导入

完整工程已经包含导入结果时，可跳过本节。协作者替换过本批源文件才需要重导入。使用本机带 NumPy 与 Pillow 的 Python：

```powershell
& 'C:\Users\userl\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'E:\little_hero\little_king\Scripts\PrepareV083Audio.py'
& 'C:\Users\userl\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'E:\little_hero\little_king\Scripts\PrepareV083Frames.py'
```

首个脚本重新合成六声音，第二个脚本核对五图集、九卡图、六声音和完整提示词，写入 metadata。它们不改变 PNG 像素。看到 `V083_AUDIO_OK` 与 `V083_FRAME_RECTS 5 /5; cards 9 /9; audio 6 /6` 后，关闭编辑器执行：

```powershell
& 'E:\epic\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe' 'E:\little_hero\little_king\little_king.uproject' -run=pythonscript '-script=E:\little_hero\little_king\Scripts\ImportV083Assets.py' '-EnablePlugins=PythonScriptPlugin,EditorScriptingUtilities' -unattended -nop4 -nosplash -NullRHI
```

完成标志为 `V083_ASSETS_IMPORT_OK`，清单写到 `Saved/V083AssetsImport.json`。脚本只写 `/Game/Art/StorybookV1/V083`，不修改地图、数据表、蓝图或存档。导入成功仍要 Play 观察显示效果。

如果贴图显示方块，先在 Content Browser 打开 `Art/StorybookV1/V083/Animations`，确认 `SP_<角色>_00` 和五个 `FB_<角色>_<状态>` 存在，再看导入日志。不要为了修图去调整角色碰撞体。若听不到新音，打开 `DA_GameData`，检查是否已为该 SoundMap 键设置空资源或关闭默认声音；显式配置优先是预期行为。

## 更换图片或调整音量

要重做图片，请保留原素材并从 [54 的提示词](54-v0.8.3Assets.md) 开始生成。五图集必须维持相同的帧顺序、右朝向、透明背景和完整轮廓。将新源文件、实际提示词和日期同时更新到 `generation.json`，重新执行 metadata 与导入脚本。不要只覆盖 `.uasset` 而丢失 PNG 和来源。

要改变施法声音音量，可以在 `PrepareV083Audio.py` 的 `SPECS` 中调整对应峰值上限，再重新合成、导入。想使用独立声音资产时，直接在 `DA_GameData → SoundMap` 给对应键指定资源，原生默认不会覆盖该选择。不要关闭并发限制来解决“某次声音没响”；大量同类声音被限流是为了避免拥挤战斗过响。
